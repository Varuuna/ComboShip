## Post-merge changes (ComboShip)

### libultraship (vendored tree, pin stays `a3f1e102e`)

Two LUS commits were hand-ported because the merge made them **mandatory** — both games now call
into them, so nothing compiled without them. The pin is deliberately unchanged; we still skip
LUS #1103 (Context destructor), so a blanket switch to `c57da1b4a` is not on the table.

- **#1141 `G_SETTILESIZE_LERP`** — soh #6902 and mm #1812 both emit `__gDPSetTileSizeLerp` and set
  `Interpreter::mInterpolationT`. Ported: the `0x4a` opcode (`gbi.h`, `lus_gbi.h`), the
  `__gDPSetTileSizeLerp` macro, the `mInterpolationT` field, `gfx_set_tile_size_lerp_handler_rdp`
  + its `rdpHandlers` entry, and the two `GfxDebuggerWindow` DL-walk cases (`G_SETTILESIZE_INTERP`
  was also missing one, so the debugger mis-walked those DLs).
- **#1157 `LoadGuiTexture` palette parameter** — soh's #6966 LUS bump changed 39 call sites (and mm
  #1805 another 5) to the 4-argument `LoadGuiTexture(name, path, "", tint)`. Rather than strip the
  `""` from 44 vendored call sites, the additive `palettePath` parameter (defaulted, so old 3-arg
  calls still compile) plus the `Palette4bpp` decode path were ported.
  Deviation from upstream: upstream passes `nullptr` for the `const std::string&` in
  `GfxDebuggerWindow.cpp`, which is UB; we pass `""`.

#1164 ("round interpolated texture tile sizes") needed no work — already vendored.

### soh

- **`Enhancements/QoL/BetterSaveMenu.cpp`** — our `COMBO_BUILD` block (commit `e0152a8b2`, which
  fired `OnExitGame`+`OnLoadGame` before `SET_NEXT_GAMESTATE` to stop a stale `gRandoContext` from
  crashing the check-tracker recalc) is **deleted**. Upstream #6984 now does this properly: it
  fires `OnExitGame` at fade-out completion and `OnLoadGame` *after* the gamestate switch, and adds
  `ShipSaveContextData::resetToSpawn` so the spawn entrance is applied after `OnLoadGame` instead
  of being clobbered by it. Keeping both would have fired each hook **twice** — precisely the
  freed-`Context` path the block existed to avoid. The file is now byte-identical to upstream.
  Note: `OnLoadGame` now also fires on the in-menu save+reload path, so the launcher's
  `gComboSaveLoadCallback` (`SOH_SetOnLoadSaveCallback`) sees a new invocation site.
- **`OTRGlobals.cpp`** — two references broken by the merge, both invisible to git because the
  files merged cleanly:
  - the include of `3drando/random.hpp`, renamed to `randomizer/rng.h` by #6947;
  - `AddElementsToPool(itemPool, GetMinVanillaShopItems(8))` in `SOH_ShuffleEntrancesForCombo`,
    which #6948 deleted → now `SohUtils::AppendVector` (`soh/util.h` was already included).

### mm

- **`BenPort.h`** — `OTRGlobals::context` reverted from upstream's raw `Ship::Context*` back to
  `std::shared_ptr<Ship::Context>`. Upstream can use a raw pointer because LUS #1103 moved Context
  ownership into LUS; we skip #1103, so `mContext` is still a `weak_ptr` and
  `CreateUninitializedInstance` returns the only strong reference — a raw member frees the Context
  immediately. `soh/OTRGlobals.h` already carries the same deviation.
- **`BenPort.cpp` `MM_DumpRandoSettings` / `MM_RestoreRandoSettings`** — excluded checks are no
  longer round-tripped as a CSV string. mm #1817 made `gRando.ExcludedChecks` a JSON array of `RC_`
  names and made `GetExcludedChecksFromConfig()` **`CVarClear` anything it finds in the old string
  form**, so the previous code silently discarded the seed author's MM exclusions on every replayed
  or joined seed. Now dumps/restores via `Rando::GetExcludedChecksFromConfig()` /
  `SetExcludedChecksInConfig()`, mirroring how `gRando.StartingItems` is already handled. Bonus:
  `RC_` names survive the enum renumbering that #1773 introduced.
- **`Rando/ExcludedChecks.cpp`** — null-guarded the `GetWindow()->GetGui()` deref in #1817's
  legacy-string migration branch. That branch fires whenever `CVars.gRando.ExcludedChecks` is still
  the old plain string, and it flushed cvars through the Gui unconditionally — but our headless
  generator (`comborando.exe`) creates a Context with **no Window/Gui** by design, so it segfaulted
  inside `GeneratePools` → `MM_DumpRandoStaticData`. Upstream never runs pool generation without a
  window, so this gap is only reachable from a combo-only mode. Behaviour is unchanged whenever a
  Gui exists; headless just skips the flush (the returned exclusion list is empty either way for a
  legacy value). Any user config carrying the old string form would have hit this.
- **`Rando/ActorBehavior/EnGirlA.cpp`** — took upstream's #1794/#1811 rewrite of
  `EnGirlA_RandoBuyFunc`, but **hoisted our `wasObtained` capture above** upstream's new
  `randoSaveCheck.obtained = randoSaveCheck.cycleObtained = true;`. Upstream's line lands before
  both combo guards, so a naive merge left `wasObtained` permanently true: cross-game shop items
  would never be delivered (`SendForeignCheck`) and shop checks would never be shared to the team
  (`BroadcastCheckObtainedIfFirst`). Also dropped the now-redundant second `obtained = true`.
- **`BenGui/Menu.h`, `MenuTypes.h`, `Menu.cpp`** — kept our `Fast::WindowBackend` typing against
  upstream's `int32_t`; that difference is the LUS API divergence, not a combo choice.
- **`BenPort.cpp`** — kept our `InitGfxDebugger()` helper (upstream replaced the call with a bare
  `GetGfxDebugger()` lookup, a no-op refactor) and our `gSettings.*` cvar names for the shared,
  OOT-rendered Graphics tab.
- **`resource/importer/Audio*Factory.cpp`** — kept the `CrossRMRegistry::GetOrActive("mm")` /
  `COMBO_OWN_RM()` pins; the non-combo `#else` branches took upstream's `GetRawInstance()` rename.
