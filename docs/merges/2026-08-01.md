# 2026-08-01 — libultraship: switched line `main` → `port-maintenance`

`libultraship` `a3f1e102e` (Kenix3 `main`) → `bbb565bd9` (Kenix3 `port-maintenance`).
soh and mm unchanged this pass, so the derived build version did not move and the port archives
did **not** need regenerating.

## Why the line switch

Every Harbour Masters port tracks `port-maintenance`; ComboShip alone tracked `main`. See the
standing-policy section in [../UPSTREAM_MERGES.md](../UPSTREAM_MERGES.md). Pre-flight confirmed the
switch is lossless: `main`'s only non-refactor commits (#1112, #1127) already exist on
`port-maintenance` as re-lands (`8a67fa4b9`, `026bbc278`), and its other 8 commits all postdate our
old pin by 6-7 weeks, so nothing here consumed them. #1127 touched a LUS CI workflow we don't even
vendor.

## Tooling fixes (scripts/upstream-merge.ps1)

- **`git mktree` via a PowerShell pipe appended CRLF**, so the vendor commit's tree entry was
  literally named `libultraship\r` and every merge path came back `invalid path 'libultraship?/...'`.
  Windows-only — CI runs the script on Ubuntu where the line ending is bare `\n`. Replaced with the
  temp-index `read-tree`/`write-tree` mechanism the docs already describe.
- **A failed merge was reported as "clean"** (the script only checked for `U`-state files, and a
  strategy failure leaves none). Now checks the merge exit code.

## The silent mis-merge (Context) — the important one

Git reported `Context.h`/`Context.cpp` as **auto-merged with no conflict** and produced code that
could not compile: two `GetRawInstance()` definitions, `.lock()` called on a `unique_ptr`, and
`SetInstance(shared_ptr)` assigning into a `unique_ptr`. It had silently interleaved two
incompatible ownership designs.

`port-maintenance` fully landed **#1103**: libultraship owns the `Context` via `std::unique_ptr`,
and `GetInstance()`/`SetInstance()` no longer exist. Our tree had deliberately refused that to keep
shared_ptr refcounting. **We adopted upstream's model**, because SoH itself was already 405-to-16 in
favour of `GetRawInstance()` — we were the outlier, and staying divergent meant re-fighting the
most-touched LUS file every pass.

- Reset `Context.{h,cpp}` to upstream, re-adding only `SetResourceManager()` (per-game RM swap;
  upstream has no equivalent and it is load-bearing for OOT↔MM).
- Converted ~72 `Ship::Context::GetInstance()` sites (soh 16 / mm 17 / combo 25 / LUS 14). Only the
  `Ship::`-qualified form was rewritten — soh's randomizer has its own unrelated `Context` class.
- Fixed two `ctx.get() == mCtx` identity checks in `ResourceManagerScope` / `OwnRMScope`.
- Fixed two latent `context->GetInstance()->GetWindow()` static-via-instance calls
  (`OTRGlobals.cpp`, `BenPort.cpp`) that only compiled while `GetInstance()` existed.
- `OTRGlobals::context` and `OTRGlobals` (mm) `context` are now raw `Ship::Context*`.
- **Teardown changed shape:** both games previously released a `shared_ptr` and soh's drop destroyed
  the Context implicitly. soh's `DeinitOTR` now calls `Ship::Context::DestroyInstance()` explicitly,
  at the same point. MM_Deinit-before-SOH_Deinit ordering is unchanged and still required.
  **This is the main playtest risk of this pass** — see [../deviations/boot-shutdown.md](../deviations/boot-shutdown.md).

## Deviations added

- `~Context` null-guards `GetWindow()` and `GetConfig()`. An uninitialized
  `CreateUninitializedInstance()` Context was not destructible; needed because
  `resource_manager_scope_tests.cpp` can no longer install one via the removed `SetInstance()` and
  now uses `CreateUninitializedInstance`. Worth upstreaming.
- Opted **out** of #1175's `ResolveResourceCached` memoization in `gfx_set_timg_otr_hash`
  (`interpreter.cpp` block 14): the cache keys on the path string alone and resolves through the
  global active RM, so with per-game ResourceManagers an entry cached under OOT could be served
  while MM is active. We keep `ActiveResMgr()->LoadResourceProcess()`. Revisit if the cache ever
  becomes RM-aware.
