## Post-merge fill-parity fix

#1840's per-house skulltula shuffle stamps the 30−N *vanilla* tokens `shuffled=true` with their own
token **inside `GeneratePools`' saveInfo** and drops them from `checkPool`. Native writes that into
the real save; combo's dump calls `GeneratePools` on a discarded local, so those tokens would reach
neither the oracle (under-counted tokens → Spider House rewards unreachable when required >
shuffled) nor the combo save. Fixed in `MM_DumpRandoStaticData`: emit them as `fixed[]` placements
of their vanilla token (`hintable=true`, mirroring native's shuffled state) — the same mechanism as
the non-shuffled boss remains right above it. Default settings (all 30 shuffled) are unaffected.

Noted, intentionally not replicated: native `OnFileCreate` now forces `RO_STRAY_FAIRIES_REQUIRED` to
25 when stray fairies are start-with. With start-with the player owns all 25 per dungeon, so any
required threshold is trivially satisfied — no logic or runtime effect in combo's pipeline.
